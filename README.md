# 🎵 Mp3-Браузер для Linux

Современное, лёгкое переосмысление классического музыкального браузера **MP3-Explorer** начала 2000-х. Написан на чистом **GJS (GNOME JavaScript)** и **GTK3** — приложение рассчитано на скорость, минимализм и бесшовную работу с локальными и сетевыми музыкальными библиотеками.

Разрабатывается на русском, автоматически переводится на английский.<br>
[English version](https://github.com/nestoris/mp3-browser)

## ✨ Ключевые возможности

Это не просто ещё один музыкальный плеер. Это мощный **браузер музыкального каталога**, спроектированный с прицелом на сетевые библиотеки.

*   **🌐 Нативная поддержка удалённых библиотек (Wi-Fi, DAV, SMB)**
    Рассчитан на библиотеки с десятками тысяч треков на медленных соединениях. Интерфейс не замирает: каталоги сканируются асинхронно, а ID3-теги подгружаются динамически по мере прокрутки или открытия папок.
*   **📦 Портативный кэш с относительными путями (локальный или глобальный)**
    В отличие от инструментов, привязывающих кэш к абсолютным путям монтирования, MP3-Browser создаёт портативные JSON-кэши прямо внутри музыкальной папки, если она доступна для записи. Если папка только для чтения (сетевой монтаж, GVFS и т.п.), кэши уходят в `~/.cache/mp3-browser/<md5>-mp3-file-cache.json` и `<md5>-mp3-tag-cache.json`. В обоих случаях сервер (например, Android/Termux) может отсканировать библиотеку один раз, а клиент (например, Linux-ПК, подключённый через GVFS) открывает ту же самую папку по другому пути и мгновенно видит все теги без повторного сканирования.
*   **🚀 Отдельный CLI-сканер (`mp3-scanner.js`)**
    Нужно просканировать 60 000 треков на headless-сервере? Встроенный CLI-инструмент строит дерево каталогов и извлекает ID3-теги (v1 и v2) без запуска GUI. Команда `apply` позволяет обновлять теги *только* для новых файлов, экономя часы сканирования.
*   **🎛️ Свой плеер**
    Программа работает как командир. Настройте произвольные shell-команды для «Play» и «Enqueue» в настройках. Используйте `mpv`, `vlc`, `termux-media-player` или любой другой CLI-плеер. Поддерживается пакетное воспроизведение через автоматически сгенерированные временные `.m3u8`.
*   **🖱️ Множественное выделение и Drag-and-Drop в стиле Thunar**
    Плавное, «нативное» множественное выделение с полноценным drag-and-drop (включая кастомные иконки перетаскивания, показывающие, сколько треков перемещается). Бросайте треки прямо в плейлисты, а папки из дерева — на список плейлистов, чтобы создать новый плейлист.
*   **📑 Плейлисты как закладки**
    Простые файловые плейлисты в JSON. Добавляйте, переименовывайте, меняйте порядок и удаляйте треки. Экспорт любого плейлиста в стандартный `.m3u8` для использования в других плеерах.
*   **🧠 Умная сортировка**
    Естественная числовая сортировка номеров треков (1, 2, ..., 9, 10) вместо алфавитной (1, 10, 11, 2). Ширина колонок, их порядок, геометрия окна и **состояние сортировки каждого плейлиста** запоминаются между сессиями.
*   **🖥️ Иконка в системном трее**
    GTK-иконка статуса даёт возможность скрыть/показать главное окно одним кликом, не закрывая приложение.
*   **🐞 Встроенная отладка**
    Запустите с `--debug` (или `-d`), и каждый внутренний шаг будет записан в `~/.cache/mp3-browser/debug.log`.

## 🛠️ Системные зависимости

Приложению нужны GJS (или CJS) и GTK3. Никаких тяжёлых обёрток вроде Electron или web-движков.

### Debian / Ubuntu / Linux Mint
```bash
sudo apt update
sudo apt install gjs libgtk-3-0
```

### Fedora
```bash
sudo dnf install gjs gtk3
```

### Arch Linux / Manjaro
```bash
sudo pacman -S gjs gtk3
```

### openSUSE
```bash
sudo zypper install gjs gtk3
```

### 📱 Android (Termux)
Можно запускать сканер и (при наличии X11-окружения вроде VNC или Termux:X11) GUI прямо на Android:
```bash
pkg update
pkg install cjs gtk3
ln -s $PREFIX/bin/cjs $PREFIX/bin/gjs
```
*(Примечание: для воспроизведения через Termux установите `termux-api` и настройте команду `Play` в настройках на `termux-media-player play %f`).*

## 🚀 Руководство по использованию

### 1. Первый запуск и настройка

Запустите браузер, при желании указав музыкальный каталог:

```bash
./mp3-browser.js /path/to/your/music
```

Любой неопционный аргумент трактуется как музыкальный корень; он добавляется в список корней на лету, если его там ещё нет. Используйте `--help` (или `-h`), чтобы увидеть справку.

При первом запуске приложение создаёт конфигурационные файлы в `~/.config/mp3-browser/`:

*   `config.ini` — корневые папки, команды плеера и лимиты сканирования.
*   `window.json` — размер окна, положение панелей, ширина/порядок колонок, последний активный корень.
*   `playlists.json` — ваши плейлисты (а также состояние сортировки каждого плейлиста под ключом `_sort`).

**Пример `config.ini`:**

```ini
[Paths]
Roots=/home/user/Music;/mnt/nas/Music

[Player]
# %f заменяется на путь к файлу или временный .m3u8
Play=mpv --no-video %f
Enqueue=mpv --no-video --append %f
# Что делают Enter / двойной клик: "play" или "enqueue"
DefaultAction=play
MultipleTracksUseM3U=true

[Scan]
MaxTrackCount=20000
LogEvery=500
```

*(Диалог настроек в GUI также доступен через `File -> Settings…`.)*

### 2. Портативное CLI-кэширование («киллер-фича»)

Если музыкальная библиотека лежит на медленном сетевом диске или сервере, её можно просканировать заранее. Сканер создаёт кэши с относительными путями (`mp3-file-cache.json` и `mp3-tag-cache.json`) прямо в музыкальной папке (если она доступна для записи), так что GUI читает их мгновенно независимо от точки монтирования.

**Проверить один файл:**
```bash
gjs mp3-scanner.js test /path/to/track.mp3
```

**Построить дерево файлов (быстро, без чтения ID3):**
```bash
gjs mp3-scanner.js scan /path/to/Music /path/to/Music/mp3-file-cache.json
```

**Прочитать ID3-теги для всего дерева (может занять время):**
```bash
gjs mp3-scanner.js tags /path/to/Music/mp3-file-cache.json /path/to/Music/mp3-tag-cache.json
```

**Обновить теги ТОЛЬКО для новых файлов (сверяет дерево с существующим кэшем):**
```bash
gjs mp3-scanner.js apply /path/to/Music/mp3-file-cache.json /path/to/Music/mp3-tag-cache.json
```

**Всё в одном: scan + apply (читает только файлы, отсутствующие в кэше тегов):**
```bash
gjs mp3-scanner.js cache /path/to/Music
```

**Всё в одном: scan + принудительное перечитывание ВСЕХ тегов (медленно!):**
```bash
gjs mp3-scanner.js cacheforce /path/to/Music
```

Выполните `gjs mp3-scanner.js --help`, чтобы увидеть все команды.

Когда вы позже откроете эту папку в GUI (неважно, `/home/user/Music` или `/run/user/1000/gvfs/dav:host=.../Music`), браузер мгновенно прочитает эти JSON-файлы и покажет библиотеку без сетевых задержек.

### 3. Управление GUI

*   **Выбор папки (сверху)**: переключение между настроенными корнями. Кнопка ↻ перезагружает текущую библиотеку — по умолчанию она переиспользует кэш тегов и читает теги только для новых файлов; **SHIFT+клик** форсирует полное перечитывание (с диалогом подтверждения, если в библиотеке больше 1000 файлов).
*   **Левое дерево**: фильтр по каталогам (поставьте галочку «Files», чтобы фильтровать по именам файлов *и* ID3-тегам внутри каталогов). Перетаскивайте папки на список плейлистов, чтобы создать новый плейлист.
*   **Таблица справа сверху**: отображает треки. Двойной клик или `Enter` — Play или Enqueue (согласно `DefaultAction`). Правый клик — контекстное меню: Play, Enqueue, Add to playlist, **Sort by…** (включая «(no sorting)») и Refresh.
*   **Панель справа снизу**: управление плейлистами. Перетаскивайте треки из таблицы файлов в плейлист или папки из дерева на список имён плейлистов, чтобы создать новый. Правый клик — контекстные действия. Клик по заголовку колонки сортирует плейлист (состояние запоминается отдельно для каждого плейлиста).
*   **Тулбары**: используйте иконки под таблицами для быстрых действий Play, Enqueue и Add-to-Playlist (поддерживается множественное выделение).
*   **Иконка в системном трее**: клик — скрыть/показать главное окно.

## 🐞 Диагностика

*   **`~/.cache/mp3-browser/scan.log`** — подробный журнал последнего сканирования каталогов (прогресс каждые `LogEvery` файлов, прошедшее время).
*   **`~/.cache/mp3-browser/debug.log`** — пишется только при запуске с `--debug` / `-d`; содержит версии GTK/GJS, пути программы и внутренние события.

---

## ⚙️ Технические детали

*   **Язык:** GJS (GNOME JavaScript) / CJS (Cinnamon JavaScript)
*   **UI Toolkit:** GTK3
*   **ID3-парсер:** собственный, высоко оптимизированный чистый JS-парсер (поддерживает ID3v1, ID3v2.2/2.3/2.4, UTF-8, UTF-16, Latin-1).
*   **Без внешних зависимостей** для разбора тегов (никаких `ffprobe` или `taglib`).
